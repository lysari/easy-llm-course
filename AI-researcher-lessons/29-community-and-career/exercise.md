# Exercise 29 — Build Your Public Presence

This exercise produces real, public artifacts — not notes in a folder. Everything here
is designed so that by the time you finish the [lesson 30 capstone](../30-capstone-research-project/lesson.md),
you have somewhere public to put it and a small audience forming around it.

---

## Part 1 — The repo (your portfolio's foundation)

Create a public GitHub repository for your work from both tracks (e.g.
`llm-from-scratch-ts` or `ai-research-notebook`). Push your implementations and
experiments. Then write the README as if it were a mini-paper
([lesson 28](../28-writing-a-paper/lesson.md) structure):

- **What this is** (2 sentences): "Everything implemented from scratch in TypeScript
  while working through an LLM + research curriculum: attention, backprop, BPE, a tiny
  GPT, and controlled experiments with proper statistics."
- **Highlights with evidence**: 3–5 bullets, each linking to code AND showing a result
  (a loss number, a generated sample, a table). Claims with exhibits, like contribution
  bullets.
- **How to run**: one copy-pasteable command per highlight (`npx ts-node ...`).
- **What I'd do differently / known limits**: the trust-building section almost no
  README has.

Checklist: [ ] repo public  [ ] README has ≥1 table or plot  [ ] every highlight runs
with one command  [ ] license file added (MIT is fine).

## Part 2 — The explainer post

Pick ONE lesson you completed where something surprised you (surprise = you have
something to say). Good candidates: attention from scratch, why √d, BPE edge cases,
seed variance being bigger than the "improvement".

Write a 800–1500 word explainer:

1. Open with the confusion you personally had ("I thought X; I was wrong").
2. Explain with YOUR concrete numbers/diagrams — not restated Wikipedia.
3. Include one runnable snippet from your repo.
4. End with what you still don't understand (invites replies — this is a feature).

Publish anywhere public with a stable URL: GitHub Pages, dev.to, Substack, Medium, or
just a `posts/` folder in your repo. Link it from the README. Then share the link once
in one community (X post or relevant Discord channel) with one sentence on what's inside.

Do not wait until it feels "good enough" — post the honest version. The next one will
be better; that's the point of doing this in public.

- share a reproduction result / plot from my repo, OR

Rule from the lesson: every question you post must include what you tried and a link to
your code. Every share must include one concrete number or picture.

Copy, fill, and put a monthly reminder in your calendar to review it:

```markdown

Month 2: capstone (lesson 30) done and written up in the repo
Month 3: reproduction repo #2 (paper: ______) published

         (MATS / residency / RE role / cold-email a professor: ______)

Each month, one honest line on what actually happened vs planned:
M1: ____  M2: ____  M3: ____  M4: ____  M5: ____  M6: ____
```
