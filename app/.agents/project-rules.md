# Project Rules

## Tech Stack
- Language & Framework: TypeScript 5.9 (strict), React 19 with JSX (`react-jsx`), React Router 8 (declarative mode, imported from `react-router`), Vite 8 with `@vitejs/plugin-react`
- Package Manager: bun (`bun.lock`). Never add a second lockfile.
- Tests: `bun:test`
- Code colours: `sugar-high` (token API only). Prettier is a dev dependency used only by the lesson snippet test.
- Page text extraction: `@mozilla/readability` (pinned, Apache-2.0), used only by the Inside real models page's data demos. `happy-dom` is a dev dependency used only by those demos' tests, to parse HTML in `bun:test`.
- GPT-2's merge rules: `public/gpt-2/vocab.bpe` with OpenAI's Modified MIT `LICENSE` beside it, fetched from the app's own folder only by the Inside real models page's tokenizer demos.
- Runs entirely in the browser. There is no server, database or auth.
- Pages are path routes: `/` is Lessons, `/playground` is Playground and `/inside-real-models/:model/:mode/*` is Inside real models (`/inside-real-models` alone goes to `/inside-real-models/gpt-2-small/use`), through React Router. Old `/take-apart/...` links are replaced with the same path under `/inside-real-models` (`movedPath` in `features/inside-real-models/inside-real-models-path.ts`). Any host must rewrite every path to `index.html`, and `dist/` can no longer be opened straight from the file system.

- `core/model`: real model code only. It never imports from `features/` and never touches the DOM.
- `features/<page>`: everything private to one page. A feature never imports from another feature.
- `shared`: only what 2 or more modules use, with no page-specific logic. Never place a file loose in `shared/`.
- New page code belongs in: `src/features/<page>/`, with a sidebar link in `src/core/layout/`
- Shared primitives belong in: `src/shared/<kind>/`
- Each UI region has its own file. `main.tsx` only mounts the layout.
- A feature's React hooks live in `src/features/<page>/hooks/`; hooks used by 2 or more modules live in `src/shared/hooks/`.
- Keep a file readable in one pass. Split by responsibility when it passes about 300 lines.

## Import Aliases & Paths
- `@/*`: `src/*`, set in both `tsconfig.json` (`compilerOptions.paths`) and `vite.config.ts` (`resolve.alias`).
- Use `@/` for imports across folders, and `./` for imports within the same folder.

## Naming Conventions
- Files: `kebab-case.ts`, and `kebab-case.tsx` for files with JSX (components). Hooks: `use-<name>.ts` exporting `use<Name>`. Shared types live in `<name>.interface.ts`.
- Components: PascalCase named function exports, e.g. `export function LossPlot`.
- Exports: named exports only, no default exports. The only exception is what `vite.config.ts` requires.
- Functions and variables: `camelCase`. Module constants: `UPPER_SNAKE_CASE`. Booleans read as questions (`isDone`, `hasAttention`).
- Types and interfaces: PascalCase with no `I` prefix. `interface` for object shapes, `type` for unions and aliases.
- CSS: kebab-case classes, `is-*` for states, `<block>--<variant>` for variants.
- Domain terms:
  - Use `layer`, never `block`, for one attention + feed-forward unit in code. Lesson text may say "transformer block" where it explains the idea.
  - Use `round`, never `step`, for one training pass (guess, score, find the cause, fix). "Step size" stays as the plain name for the learning rate.
  - `stage` is a left-column card. `part` is what the screen calls a right-column card, and the code calls it `FlowStep` today. `FlowStep` and `STEPS` are not training rounds.
  - `weights` in code are the "numbers" on screen. `token` in code is a "word" on screen.

## Core Shared Helpers (Do Not Duplicate)
- Markup: JSX only. Never build HTML strings; JSX escapes text itself. Keep keys stable so hover, focus and scroll survive a redraw.
- Formatting: `percent`, `count`, `showWord`, `shortList` (`shared/utils/format.ts`), `joinTokens` (`core/model/corpus.ts`). the Inside real models page's compact card numbers (124M, 8.03B) are `showAmount` in `features/inside-real-models/real-place.ts`.
- Tiny corpus constants: `START_CHOICES`, `TEST_WORDS` and `TEST_ANSWER` (the test sentence and its right next word) and `GUESSING_LOSS` (the loss of random guessing) live in `core/model/corpus.ts`, used by every page.
- Charts: the `ChanceBars` and `LossPlot` components in `src/shared/components/`. `PLOT` (plot size and margins) lives in `loss-plot.tsx`; Lessons' own plots read it from there.
- Sampling and writing: `applySampling`, `writeText`, `nextOptions`, `pickToken` in `core/model/generate.ts`.
- Seeded randomness: `seededRandom` in `core/model/random.ts`. Never use `Math.random` for anything a test or a comparison depends on.
- Icons come in two styles, never mixed in one group:
  - Concept (object) icons: `ConceptIcon` (`<ConceptIcon name="layers" size="card" />`) in `src/shared/components/concept-icon.tsx`, drawn from the one `CONCEPT_SHAPES` table in `concept-shapes.tsx` (24 grid). Each is the filled outline of the object it names, its parts in at least two tints of its family colour (`ci-light`, the body's top-to-bottom gradient, `ci-deep`, `ci-line`), never a tile or a shape with white marks on it. `ConceptName` (`src/shared/interfaces/concept.interface.ts`) is a union, so a wrong name fails the typecheck. Sizes: `nav` 20px, `chip` 18px, `card` 26px, `drawer` 28px (`--icon-*` in `variables.css`). A derived concept is its base drawing plus a bottom-right badge (`plus`, `check`, `repeat`). They sit bare, with no tile behind them; on the active card band they turn white and pale blue (`--band-icon-*`).
  - Action icons: `Icon` (`<Icon name="chevron" />`) in `src/shared/components/icon.tsx`, thin one-colour 16px lines at 1.5 stroke from the `ICON_PATHS` table (`IconName` union); add is green (`--action-add`), remove/trash is red (`--action-remove`), the rest take the text colour.
- Flow cards: `FlowCard` in `src/shared/components/flow-card.tsx` (styled by `flow-card.css`) draws the `<article class="card">` with `.card-head` (concept icon, title, lesson label, `StatusPill`) and `.card-body` (task line, foot value and action buttons), and clicks itself on Enter or Space (`activateOnKey` in `src/shared/utils/keyboard.ts`). The active card (`.card.is-active`), the card the user is focused on, shows the gradient header band (a `::before` layer filled with `--card-band`: `--band-deep` → `--band-sky`, a calm deep blue to sky blue, masked by `--card-band-fade` so it fades out below `--card-band-height`) around the near-solid rounded `.card-body` (`--card-raised`), with white header text, icon and round pills (`--band-*` colours, so every header text and icon keeps 4.5:1 in both themes); it has no coloured ring. The active card is the card whose drawer is open, if any, else the deepest selected card: on Lessons the open part, else the selected stage (plus the part a training run is on), and on Inside real models the open card, else the deepest card of the selected path (`activeIdOf` in `models.ts`). Every other selected card (the selected stage while a part is open, the rest of the selected path) gets the quiet `.card.is-selected` (neutral border and shadow). An open card has no ring of its own; keyboard focus keeps the `:focus-visible` outline. Props: `ref`, `id`, `icon`, `title`, `lesson`, `status: Status`, `task`, `foot: ReactNode`, `actions: CardAction[]`, `onCommand(command)`, an optional `className` added after `card` (state classes `is-dim`, `is-entering`, `is-active`, `is-selected`), and any other article attribute (`aria-*`, `style`, `onClick`) passed through. An action button stops its click, so the card's `onClick` does not run. `aria-label` is the title. Only Lessons uses `FlowCard`; the Inside real models page draws its own `PartCard` from the same shared pieces (`.card` and its state classes, `.card-body`, `.card-title`, `ConceptIcon`, `StatusPill`, `activateOnKey`, `.action`), with no lesson label.
- Status pill: `StatusPill` (`{ status: Status }`) in `src/shared/components/status-pill.tsx`. `Status` and `CardAction` live in `src/shared/interfaces/card.interface.ts`. `Status` also has `"ground-zero"`, shown as "Smallest step" and used only by the Inside real models page. The other pills read "Press the button" (`needs`), "Train first" (`queued`) and "Read only (not run here)" (`lesson`). Its `.pill` styles, the card heading classes (`.card-head`, `.card-title`, `.card-lesson`) and the `.card` shell + `.card-body` inner surface with its state classes (`is-dim`, `is-active`, `is-selected`, `is-entering`) live in `global.css`, because `FlowCard`, the Inside real models page's `PartCard` and `Drawer` use them; `flow-card.css` keeps only `FlowCard`'s task line and foot.
- Flow links: `FlowLinks` (`{ id, drawing: LinkDrawing | null, pathIds: string[], glowIds: string[] }`, renders `svg.links` with that id, styled by `flow-links.css`; Lessons passes `links`, each Inside real models page column `inside-real-models-links-<parent id>`, so mounted pages never share an id) and `STAGGER_MS` in `src/shared/components/flow-links.tsx`; `useFlowLinks(elements, options)` in `src/shared/hooks/use-flow-links.ts` measures the lines (`measureLinks`). Each path keeps `fromId`, the card it starts from (the parent, or the card before a nested child), and `toId`, the card it ends at; each dot keeps `fromId`. `pathIds` are the cards on the path from the first card to the active card, and `glowIds` the cards whose incoming line moves (Lessons passes the selected stage, then the open part with the part before it if it is nested, and the open part as `glowIds`; with nothing open only the stage and no glow; during a training run the chain to the running part and the running part instead, as `activeIdsOf` in `flow.ts` returns; every Inside real models column passes the selected path plus the open card, `pathIdsOf` in `models.ts`, and the active card as `glowIds`, so the column that holds it finds the line into it). Every line first draws in quiet (`--link-quiet`), one `STAGGER_MS` after the one before. A line whose `fromId` and `toId` are both in `pathIds` (a path line) is then drawn again on top of all the quiet lines, with no delay, in its own `userSpaceOnUse` `<linearGradient>` (`<svg id>-gradient-<toId>`, from its `startX` to its `endX`, stops `--link-deep` and `--link-sky`, the same blue family as the card band), and its start dot is `is-active` in `--link-deep`. Only a path line whose `toId` is in `glowIds` (the last line, into the active card) also gets the moving glow (`.link-glow`, the same path with a short dash moved along it, one pass per `--links-glow-duration` if a container sets it, else `--motion-flow-duration`, eased by `--motion-flow-ease`, hidden under reduced motion; Lessons sets `--links-glow-duration` to `STEP_ORDER_MS` on `.flow` during a training run, `RUN_GLOW_STYLE` in `flow.ts`, so one pass fits one training step); the rest of the path stays still. Every other line, including the lines out of the active card to cards off the path, and every other dot is the neutral `--link-quiet`. `elements`: `flowRef` (the positioned container the SVG fills), `childColumnRef` (the child column; the trunk runs halfway to it), `parentCards` and `childCards` (`RefObject<Map<string, HTMLElement>>` by id). `options`: `parentId`, `childIds` (memoized), optional `nestedIds` (a nested child links from the card before it, with a dot), `isShown`, `width` (measures again on change). `LinkDrawing` lives in `src/shared/interfaces/link.interface.ts`.
- Drawer: `Drawer` in `src/shared/components/drawer.tsx` (styled by `drawer.css`) draws the right-side overlay `aside` with header (concept icon, title, an optional lesson line, `StatusPill`, ✕) and a scrolling body holding `children`. Props: `ref`, `id`, `icon`, `title`, optional `lesson` (the line under the title; Lessons passes it, Inside real models leaves it out), optional `status` (no pill when left out), `bodyKey` (a new key remounts the body so its scroll resets, without sliding in again), `onClose`, `children`, and an optional `panel` (a second, wider column beside the body; the drawer then opens wide as `.drawer--wide`, `--drawer-wide-width` / `--drawer-wide-share`). `useDrawer(triggers)` in `src/shared/hooks/use-drawer.ts` returns `{ openId, drawerRef, toggle(id), close }` (`close` is stable), and closes on Escape or a click outside the drawer and the cards in `triggers`, moves focus in on open and back to the card on close. Width is `--drawer-width`; at narrow width it is a full-screen sheet.
- Narrow width: `useWindowWidth()` and `NARROW_WIDTH` (960px, matching the stylesheets' `max-width: 960px`) in `src/shared/hooks/use-window-width.ts`.
- Snippets: `FormulaBlock` (`{ formula: Formula }`), `CodeBlock` (`{ code: string }`) and `CopyButton` (`{ text, label }`) in `src/shared/components/` (`formula-block.tsx`, `code-block.tsx`, `copy-button.tsx`, styled by `snippet-blocks.css`). `Formula` and `FormulaTerm` live in `src/shared/interfaces/formula.interface.ts`. Code colours come from `sugar-high` tokens rendered as JSX spans, never its HTML string.
- Frame loops: `use-session.ts` (Lessons), `use-training-loop.ts` (Playground) and `use-tiny-lab.ts` (Inside real models) stay in their features; they drive different objects in different ways, so there is no shared loop hook.
- Network, auth and notifications: none exist, and none are needed. A saved web page is stored in the app, never fetched. Large data files a demo needs (GPT-2's `vocab.bpe`) are served from the app's own `public/` folder and fetched only when that demo opens; nothing is fetched from another site.

## UI & Styling Conventions
- Rendering: React components with JSX, under `StrictMode`. No `dangerouslySetInnerHTML` and no `innerHTML`. Every effect cleans up its listeners, timers and frames.
- Live training: keep the mutable run object in state and redraw on each animation frame from a hook (`use-training-loop.ts` in Playground, `use-session.ts` in Lessons); never copy the model into state.
- Styling: plain CSS with custom properties, no preprocessor and no CSS framework.
- Flow layout: `.top`, `.top-stats`, `.column`, `.part-column` and the drawer body classes `.tasks`, `.task`, `.why` live in `global.css`, used by Lessons and Inside real models. `.fleet`, `.flow` and `.part-row` stay in `lessons.css`.
- Global styles live in `src/shared/styles/`:
  - `palette.css`: base colours first, then design colours as `var()` of a base colour; a colour that differs between light and dark is one `light-dark(var(--light-base), var(--dark-base))` value on `:root` (with `color-scheme: light dark`, so Auto follows the system), `:root[data-look="light"]` / `[data-look="dark"]` only set `color-scheme`, and `:root[data-look="fresh"]` overrides design colours for Fresh. Components read design colours only. Code colours are `--code-identifier`, `--code-keyword`, `--code-string`, `--code-comment`, `--code-class` (numbers and capitalized names), `--code-property`, `--code-sign` and `--code-line-number`.
  - `variables.css`: radius, spacing, type, shadow, motion and layout sizes, including their `:root` overrides at each breakpoint.
  - `fonts.css`: `@font-face` and font variables. Inter is served from `public/fonts/`, never from a font CDN. `--font-mono` and `--font-math` are system font stacks.
  - `global.css`: element defaults and shared classes.
- A page's own variables stay in its stylesheet, named `--<page>-*`. Sizes a shared component reads (`--tile-size`, `--card-foot-height`, `--drawer-width`) live in `variables.css`.
- Never write a colour, spacing, radius, type, border, shadow or timing value in component CSS. Read a token.
- Motion: 150-350ms with ease-out, through `--motion-*` tokens. The spinner's constant rotation is the one linear animation. The glow on the line into an active card is the one other looping animation (`--motion-flow-duration` 1600ms, `--motion-flow-ease` ease-in-out; during a Lessons training run one pass per `STEP_ORDER_MS`, 450ms), and stops under reduced motion.
- Inside real models page look: the Lessons Fleet cards and lines in left → right columns that keep the whole selected path visible, scrolling sideways inside their own pane (stacked at 960px and below), with a breadcrumb that only shows the mode and path and scrolls to a card, a "Use a model | Build a model" segmented switch and a native `<select>` for the model; the user's sentence and the tiny demo model's learning show only inside the demos that use them. Column 1 holds the numbered step cards. Cards are "Simple first" (chosen by the user 2026-11-09): number badge or concept icon, title, one plain sentence (`summary`), an in → out line, a real-model numbers strip (the headline, then one more sourced real fact, stacked at full card width, with no model name: the column title names the model once), and a foot with "Look inside (N parts) ›" (opens the next column) and "Explain this ›" (opens the drawer), or only "Explain this ›" on a leaf card; a card with copies shows "N of these" under its title, never "× N"; a part may carry `term`, one soft line that explains a hard word where it first appears (token, vector, logit, head); everything else lives in the drawer.
- Lessons page look: reference video of a "Fleet" dashboard. Stages on the left, parts on the right, joined by lines. Clicking a part card opens its detail in a right-side overlay drawer. A single long row running to the right was tried and rejected.
- Playground page look: reference video of a "Guard risky commands" rule builder.
- Every chip and control must change something real. Never add a control that only looks like the reference.
- Text is simple English, written directly in the code.

## Verification Commands
- Lint: none. There is no linter or formatter for project source. Prettier only checks lesson code snippets, inside `bun run test`.
- Typecheck: `bunx tsc --noEmit`
- Test: `bun run test`
- Build: `bun run build` (runs the typecheck first)
- Run: `bun run dev`
- UI changes: check them by hand in Chrome, in light and dark and at phone width, and report anything left unchecked.
